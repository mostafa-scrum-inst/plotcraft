# F4 — 3D dollhouse, vegetation, free camera, time of day and seasons: feature plan

Owner: Tech Lead. Shared decisions: `architecture.md` (A-n), especially A-9 to A-13 and the allowed r128 API list in A-10.

## Stories covered
F4-S1 See the house on the plot, F4-S2 Look from any angle, F4-S3 Change time of day and season. Goal G6 (performance proxy).

## Technical approach
- **The riskiest, locally untestable code lands first** (CTO): renderer set-up, render loop, resize, colour handling, batching and the hand-written camera controls are all in T1, with a minimal but complete house shell, so the hosted page can be checked after one task. T2 and T3 then only add data-driven geometry and parameter changes on top of proven plumbing.
- **Hand-off**: `PC.house.build(state)` (A-9) is the only input of the 3D layer. T1 builds levels/rooms/core/roof descriptor/site rectangles; T2 fills `furniture`, `seating`, gate and entrance details; T3 fills `trees` and `shrubs`.
- **Geometry**: only boxes, quads and one prism, merged by `PC.three.BoxBatch` into one mesh per level and kind with vertex colours; vegetation as three `InstancedMesh`. Maximum house = 22 meshes (A-11).
- **Conservative r128**: only the API surface of A-10; the strict mock (`tests/three-mock.js`, created in T1) throws on anything else, and every 3D test runs against it. Colours pass through `PC.three.col` (sRGB -> linear) except `scene.background`.
- **Camera**: pure pose maths in `PC.cam` (node-tested), thin Pointer Events adapter (A-12).
- **Time/season**: pure `PC.sky.compute` over the Designer's tables, applied by `PC.three.applyLook` without rebuilding (A-13).
- **Failure path**: no `THREE` or no WebGL -> in-page message in stage 5; stages 1–4 keep working (the 2D e2e suites already run with the three.js request aborted).

## Riders from the F1 feature review
- F1-S5 "Skip to 3D" really reaches the 3D view and G1's tap count (6 taps at most): F4-T1; PM re-checks at the F4 review.
